# Mind Universe 个人后台发行包

这套发行方案的目标是：你使用同一套 Mind Universe 网页，但聊天转发、语音和后台任务由你自己的 Cloudflare 后台处理，相关额度和费用属于你自己的账号。

这里是发行资料与成品包的存放处，不是完整源码仓库。软件按[个人非商业许可](LICENSE.txt)提供，不是开源软件。

## 当前：内测准备

独立[发行仓库](https://github.com/richzorya/mind-universe-release)目前为私有仓库，仅获授权的内测成员可访问。

目前这份仓库说明不代表已经发布可安装版本。正式网页地址、经过验证的个人后台安装包和安装入口尚未在此公布；没有安装按钮，也不需要寻找隐藏链接。不要把开发预览网址当成正式发行地址。

网页的个人后台连接入口按“设置 → 个人后台”设计，使用后台地址与配对码。自动登录 Cloudflare 并安装后台的流程尚未验收完成，当前不能当成手机一键安装使用；本方案不通过把你的 Cloudflare 管理令牌交给维护者来绕过这一缺口。

内测需要先完成[发布前检查](RELEASE_CHECKLIST.md)。在某个 Release 明确写出安装前提、已验证功能、已知限制和卸载方法之前，请不要上传真实聊天记录或填写真实密钥来试装。

## 这套方式怎么用？

- **网页**：统一托管在 Cloudflare 或 Netlify。普通用户不必自己部署网页，也不必同时注册这两家平台。
- **个人后台**：安装在你自己的 Cloudflare 账号中。其他用户不会共用你的后台账号或额度。
- **模型与语音**：继续在网页原有的 API Keys 设置中填写自己的密钥。个人后台不是免费 AI，模型和语音费用仍由供应商分别计算。

设计目标是“你的手机 → 你的个人后台 → 你选择的模型或语音服务”。是否已经达到这个目标，以对应发行版本的验证结果为准；不会因为换了一个后端地址就自动覆盖所有功能。

网页文件下载仍经过网页托管服务。开启个人后台，也不代表云平台、模型服务商或你的设备看不到相关数据，详见[隐私说明](PRIVACY.md)。

## 安装前需要什么？

只有下列条件全部具备，后面的安装流程才可执行：

1. 本仓库已提供一个明确标记为可安装的 Release，包含成品包、校验值、版本兼容说明和实际安装指引。
2. 该 Release 已列出正式网页地址、支持的 Cloudflare 资源及其计费前提。需要付费套餐时必须事先说明，由你决定是否开通。
3. 你可以登录自己的 Cloudflare 账号，并有权在选定账号中创建所需资源。
4. 你能在当前网络中打开网页并连接个人后台。中国大陆网络可用性需要自行验证，不保证任何地区始终可用。
5. 需要 AI 或语音功能时，你已有相应供应商的有效账号与密钥，并了解费用。

尚未提供可安装 Release 时，以上不是已经能“一键完成”的操作教程。若某个版本必须使用电脑或终端，其 Release 必须先写明，不能把这一步藏在手机安装过程中。

## 有可安装版本后：手机使用顺序

1. 在本仓库的 **Releases** 中打开该版本说明，只使用其中列出的安装包和网页地址。GitHub 的“Download ZIP”只是仓库文件快照，不等于安装好的应用。
2. 按该版本的实际指引，将成品后台安装到自己的 Cloudflare 账号；授权前核对目标账号、资源、权限和费用。不要把 Cloudflare 管理令牌发到聊天、Issue 或评论里。
3. 打开正式网页，进入“设置 → 个人后台”，填入自己的后台地址与配对码，并按该版本说明完成连接。连接失败时先排查，不要转用来源不明的公共后台。
4. 在网页原有的 **API Keys** 设置中填写模型或语音密钥。后台连接凭据和模型密钥是不同的东西，不要互相代填。
5. 先用不含隐私的短消息测试，确认网页显示的是自己的后台，并在自己的 Cloudflare 账号中核对请求。后台回复、语音和实时通话分别按 Release 的验收说明测试，不用一次聊天成功代替全部通过。
6. iPhone 用户可在 Safari 的分享菜单中选择“添加到主屏幕”。换网址或换设备前先备份；不同网址通常使用不同的本地数据空间，旧记录不会自动跟过来。

升级或停用时，先备份，再按对应 Release 的迁移、回滚或卸载说明操作。关闭网页不等于删除云端后台，也不一定停止已经创建的任务或费用。

## 如果你也想自己部署网页

这部分是可选的；普通用户使用正式网页即可，不需要每人都建前端站点。当前仍是私有候选包，没有正式公开入口。

1. 从该版本附件下载前端包：Cloudflare 选择 `mind-universe-cloudflare-pages.zip`，Netlify 选择 `mind-universe-netlify-static.zip`。不要上传整个 GitHub 仓库，也不要把后台包上传为网页。
2. **Cloudflare Pages**：在 Workers & Pages 创建 Pages 应用，选择直接上传成品，把前端 ZIP 或解压目录交给平台。选择上传成品，不是连接源码仓库。若该版文件数超过控制台上传限制，改用官方 Wrangler 上传解压目录，不能删文件凑数。[官方步骤与限制](https://developers.cloudflare.com/pages/get-started/direct-upload/)
3. **Netlify**：选择手动部署，把前端包解压后的目录拖入上传区域；目录第一层应有 `index.html`，不需要填写构建命令或连接源码 Git 仓库。[官方手动部署说明](https://docs.netlify.com/deploy/create-deploys/)
4. 保存平台给你的 HTTPS 网页地址；安装个人后台时，把这个精确地址加入允许访问的网页名单。然后打开该网页，按上面的手机使用顺序连接自己的后台、填写 AI 密钥。

网页发布成功只说明文件已上线，不能代替后台安装。首次部署、后续换域名或更新版本都先用无隐私内容测试；同一站点更新时保留原网址，换网址前先备份。

## 当前候选版的后台保护

沿用应用已有的后台设备与实例每日 500 次任务保护，按 UTC 日期恢复，不是 Cloudflare 的免费额度；当前没有关闭这项保护的用户开关。达到上限后不再启动对应的新后台模型任务，已有结果仍可收取，普通前台聊天不按这项后台任务计数。云端生成结果最多保留 72 小时，收取确认后清除；请及时打开应用收取，重要内容另做本机备份。平台与模型服务商还可能有独立限制或费用，以上数值不代表免费承诺。
