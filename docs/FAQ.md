# 常见问题

[返回首页](../README.md) · [安装教程](INSTALL.md)

## 需要电脑吗？Windows 可以用吗？

主要安装流程通过浏览器完成，手机和电脑都不需要终端命令，Windows 也无需运行旧脚本。手机完整授权、部署和主屏幕使用仍需按[版本说明](../CHANGELOG.md#使用限制)验收。可选的旧 `install.mjs` 只面向 macOS / Linux，不应把它当作 Windows 原生安装器。

## Cloudflare 和 Netlify 要同时注册吗？

不必。自己的后台需要 Cloudflare，官方部署按钮还会连接 GitHub。使用统一 Netlify 网页无需注册 Netlify；只有自己在 Netlify 托管网页时才需要 Netlify 账号。

## 这是免费的吗？

软件按[个人非商业许可](../LICENSE.txt)提供，不收取该范围内的软件许可费。云平台、域名、模型和语音是不同服务，可能有免费额度或产生费用，互不抵扣。“免费部署”不等于 AI 免费使用，具体以自己账号的套餐与账单为准。

平台说明：[Workers](https://developers.cloudflare.com/workers/platform/pricing/)、[D1](https://developers.cloudflare.com/d1/platform/pricing/)、[Workflows](https://developers.cloudflare.com/workflows/reference/pricing/)、[Netlify](https://www.netlify.com/pricing/)。额度耗尽后可能拒绝请求或产生额外费用，取决于相应套餐。

## 几种地址和密钥有什么区别？

| 名称 | 来源 | 用途 |
| --- | --- | --- |
| 网页地址 | 统一网页或自己托管的网站 | 打开应用；必须是后台允许的准确来源 |
| 后台地址 | 自己的 Cloudflare Worker | 填入“设置 → 个人后台” |
| 配对码 | Mind Universe 在设备上随机生成 | 在应用中登记设备，不是 Cloudflare 密码 |
| INSTALL_CONFIG | 同一次本机生成 | 只粘贴到自己 Worker 的同名 Secret，包含完整安装秘密 |
| 模型 / 语音 API Key | 自己选择的服务商 | 继续使用原 API Keys 和模型、声音设置 |

Cloudflare 账号授权在官方网页完成，不要把管理令牌交给作者、贴到聊天或填入应用。

## 安装失败怎么办？

- **登录或授权受阻**：看官方页面的具体提示，确认账号、仓库权限、验证码或双重验证；不要因为某个接口无权限就反复退出登录。
- **没有 INSTALL_CONFIG 输入框**：部署后在自己的 Worker **Settings → Variables and Secrets** 中添加同名 **Secret**，粘贴原配置，保存部署；配置完成前业务接口拒绝请求。
- **复制失败或配置无效**：恢复已保存的 `MU-installation` JSON，重新复制完整长字符串，不能用配对码替代它。
- **创建资源或部署中断**：先在自己的 Cloudflare 检查已经创建的 Worker、D1 和 Workflow，保留原配置，不要连续点击首次安装创建重复资源。
- **额度或付款提示**：先核对套餐与费用，不要盲目开通付费项目。

反馈时只提供不含秘密的错误提示、版本、设备和失败步骤，不公开安装文件、完整日志或私人聊天。

## 后台地址打开后为什么不是聊天页面？

它是你的后台服务入口，根页面仅说明用途并给出网页链接，不展示配置或配对码。请打开网页，在“设置 → 个人后台”连接；后台地址能显示说明页，不代表配对、模型或通知都已通过检查。

## 网页能打开，但后台连接不上？

核对后台 URL、对应配对码，以及当前网页是否在该安装配置的准确允许来源中。不同域名不能自动互换。再检查自己的云资源、额度及网络，连接失败不会自动改用作者的后台。

网页和后台的网络可达性需要分别确认；更换 Cloudflare Pages / Netlify 网页不一定能解决 workers.dev 无法连接的问题。

## 关闭准备页、清缓存或换浏览器怎么办？

恢复保存的 `MU-installation` JSON，不要重新生成配置。清 HTTP 缓存与清网站数据不同：清网站数据、隐私浏览结束或切换浏览器可能丢失准备内容和设备凭据。新设备重新配对不等于恢复旧聊天；聊天需另用应用备份迁移。

如果只是忘记配对码，已有设备通常仍可使用；新设备需先恢复原安装文件。文件也丢失时保留现有云资源并寻求恢复帮助，不要重新生成加密和通知密钥。更换配对码不会自动撤销已登记设备。

## 自定义模型中转地址能用吗？

支持符合当前模型接口规则的公网 HTTPS 中转地址，包括自定义域名与端口；不支持内网、IP 直连、凭据嵌入 URL、跳转或任意管理接口。模型、协议、路径和授权方式仍须与服务商匹配。不要为排错关闭鉴权；反馈服务域名和脱敏错误即可。

## 我的数据会经过作者后台吗？

个人后台版的模型、语音和后台任务走当前连接的实例，失败时不会借用作者共享后台。网页下载经过托管平台，AI 请求仍需你的云平台和服务商处理相关内容；自有后台不等于完全离线。详见[隐私说明](../PRIVACY.md)。

## 为什么后台任务暂停，或者旧结果找不到了？

现有后台保护是每设备、每实例每个 UTC 日各最多 500 次后台任务；当前没有关闭开关。任一预算耗尽会暂停相应的新后台模型任务，已有结果仍可收取，下一 UTC 日恢复。这不是云平台免费额度，普通前台聊天不按此项预算计数。

云端结果最多保留 72 小时，收取确认后清除。请及时打开应用收取并备份重要内容；模型和平台还可能另有限制。

## 更新、迁移与停用

### 怎样更新？

先备份，关闭后台回复和自主聊天，确认云端停止并收取在途结果。使用统一网页时，网页由提供方更新；自己托管时，向原站点上传对应新版网页包，保留网址。

自己的后台副本由自己更新。阅读版本兼容和迁移说明，将新版成品更新到自己的安装仓库后重新部署；不要再次生成配置、复制出新实例或替换原数据库。继续使用原 `INSTALL_CONFIG`、后台身份、D1 和 Workflow 名称。数据库迁移后不保证直接上传旧版就能回退。

旧命令行安装仍沿用原私有安装目录与 `--apply`，不重新执行 `--prepare`。不要把两种安装方式的秘密混用。

### 多个后台怎样切换？

可以保存多个后台，选择当前要连接的一个。切换或断开前先停用原后台任务，确认云端清理并收取结果；无法确认时保留原连接。后台列表不会自动同步到其他设备，也不代表各实例同时服务当前页面。

### 换手机、浏览器或网址呢？

先在旧设备、旧网址导出备份，再到新环境导入并配对。同一个 Cloudflare 账号不会自动同步聊天和 API Keys。更换网页域名还需调整后台允许来源，保留原身份和密钥，不能通过重新生成配置来“更新网址”。

### 不用了，怎么停用？

先停止后台回复和自主聊天、确认云端停止、收取结果并导出备份，再断开应用连接。断开不会自动删云资源或撤销设备。

确定不再需要时，在自己 Cloudflare 的该安装项目中逐项核对 Worker、两个 Workflow 和 D1 后手动删除，不要删其他项目。删除数据库后，重新安装不能恢复其中数据。网页关闭或本地断开不等于云端已停止，平台既有费用和备份另按平台规则处理。
