# 常见问题

[返回首页](../README.md) · [安装教程](INSTALL.md) · [学习交流使用条款](../LICENSE.txt) · [免责声明](../DISCLAIMER.md)

## 已经部署了，网址去哪里找？

如果要找**日常聊天的网页**，直接打开 [Cloudflare 网页](https://mu-beta.pages.dev/)或 [Netlify 网页](https://mu-beta.netlify.app/)。

如果要找填在应用里的**后台地址**：打开 [Cloudflare 项目列表](https://dash.cloudflare.com/?to=/:account/workers-and-pages)，选择安装时的账号和 Worker 项目，打开 **Domains（域名）** 页（旧界面为 **Settings → Domains & Routes**），复制 `workers.dev` 那一项的 HTTPS 网址。不要复制 `dash.cloudflare.com` 管理页面地址。[逐步找回后台地址](INSTALL.md#找回后台地址)

以前连接成功过的设备，也能在应用“设置 → 个人后台”查看当前地址及“已保存的后台”。找不到网址不需要重新部署；安装备份文件不会保存后来部署出来的网址。

## 配对码是什么？为什么 Cloudflare 没显示？

配对码是允许设备连接你后台的口令，由安装准备页生成，Cloudflare 不会另发。它不是模型 API Key，也不是安装配置 `INSTALL_CONFIG`。

在原安装准备页点 **4. 连接后台 → 复制配对码**；“查看配对码”可看原文。原页面已关时，打开[安装准备页](https://mu-beta.pages.dev/install.html)，点“恢复已有安装备份”，选原 `MU-installation-….json`，再进入第 4 步复制。

新版配对成功后会把配对码保存在当前设备、当前网址的独立设备凭据库。在该后台旁点“编辑”，可以用小眼睛查看或点“复制配对码”。旧记录没有保存过时，在编辑表单点“导入安装备份”；应用核对后台身份并重新配对，成功后才保存。[完整找回办法](INSTALL.md#找回配对码)

Cloudflare 保存的 Secret 不支持查看原文，应用也不能从服务器找回原配对码。请保管原安装文件；普通聊天备份与 API Keys 包不包含后台配对码及设备凭据。

## 需要电脑吗？Windows 可以用吗？

主要安装流程通过浏览器完成，手机和电脑均可操作，无需终端命令。请按[安装教程](INSTALL.md)完成账号授权、部署、配对和消息测试；当前版本的使用条件见[更新记录](../CHANGELOG.md#使用说明)。旧 `install.mjs` 只面向 macOS / Linux，Windows 用户请使用浏览器流程。

## Cloudflare 和 Netlify 要同时注册吗？

不必。自己的后台需要 Cloudflare；新安装先在 GitHub Fork 官方仓库，再让 Cloudflare 连接自己的 Fork 读取程序。使用统一 Netlify 网页无需注册 Netlify；只有自己在 Netlify 托管网页时才需要 Netlify 账号。

## 两个网页能用同一个后台地址和配对码吗？

可以。两个内测网页来自同一套应用代码，个人后台也使用同一套发行模板与安装流程；网页托管平台的部署设置由各自平台处理。默认安装资料允许 Cloudflare 和 Netlify 两个内测域名连接，所以已经部署好的同一后台地址与配对码可分别填入两边“连接后台”。

两边的聊天、API Keys、后台连接和保存的配对码各自在当前网址下存储，不会自动同步。更换日常入口前先备份；自己部署的第三个网页地址还须加入后台允许来源。

## 为什么我的 Fork 数量没有增加？

旧流程由 Cloudflare 复制模板到新账号，那是独立仓库，GitHub 不把它计为原仓库的 Fork。新的安装流程要求先点 [Fork 官方仓库](https://github.com/richzorya/mind-universe-release/fork)，在 GitHub 完成 **Create fork**，再把自己的仓库网址粘贴回准备页核验。只有保留官方来源关系的 Fork 才能通过，普通复制或导入的仓库不会因此转为 Fork。

已有独立副本和已部署后台可以继续使用，不需要为了 Fork 数量重装或删除数据。更新办法见[怎样更新](#怎样更新)。

## 修改 GitHub 用户名或仓库名后，需要改链接吗？

需要把使用中的入口更新为新网址：自己的安装准备页重新粘贴新仓库地址并核验，自己发布的教程、快捷入口和 Git 远端也使用新地址。GitHub 通常会重定向旧仓库链接，但旧路径被重新使用后可能失效，不应长期依赖。[仓库改名说明](https://docs.github.com/en/repositories/creating-and-managing-repositories/renaming-a-repository) · [用户名改名说明](https://docs.github.com/en/account-and-profile/concepts/username-changes)

仓库改名会保留 Fork 的来源关系，准备页依据仓库身份核验来源。已经运行的 Worker 和其 `workers.dev` 地址不会因为 GitHub 改名而自动改名；到原 Worker 的 **Settings → Build** 核对仓库连接和监听分支，确认下一次构建正常。作者更新官方仓库名字时，已发布页面里的硬编码入口也需要随版本更新。

## 这是免费的吗？

本产品仅供个人学习和技术交流使用，作者不收取该范围内的使用费用，具体约定见[学习交流使用条款](../LICENSE.txt)。云平台、域名、模型和语音由各服务商分别计费，请以自己账号的套餐、额度和账单为准。即使云平台部署在免费额度内，调用 AI 服务仍可能产生费用。

平台说明：[Workers](https://developers.cloudflare.com/workers/platform/pricing/)、[D1](https://developers.cloudflare.com/d1/platform/pricing/)、[Workflows](https://developers.cloudflare.com/workflows/reference/pricing/)、[Netlify](https://www.netlify.com/pricing/)。额度耗尽后可能拒绝请求或产生额外费用，取决于相应套餐。

## 几种地址和密钥有什么区别？

**安装后台**是在自己的 Cloudflare 账号中创建服务，首次使用时做一次；**连接后台**是把当前设备连到已经安装的服务。换设备或重新配对使用“连接后台”，不需要重新安装一套云资源。完整解释也可在应用“设置 → 个人后台 → 功能说明”查看。

聊天网页供你打开应用；后台地址指向自己的后台服务；配对码是连接该服务的口令；安装配置 `INSTALL_CONFIG` 是给 Cloudflare 保存的整套安装秘密；API Key 是 AI 服务商给你的调用密钥。它们不能互换。

[查看每一项的含义、复制位置和粘贴位置](INSTALL.md#先认清要用的内容)。已经配好的 API 密钥与模型不会因配对而要求重填；如果换了聊天网址，需要先从旧网页备份导入，不同网址不自动共享本机资料。

Cloudflare 账号授权在官方网页完成，不要把管理令牌交给作者、贴到聊天或填入应用。

## 安装失败怎么办？

- **Fork 核验失败**：确认粘贴的是自己已创建、公开可用的官方 Fork 首页；独立复制的仓库不符合此安装入口。请求受限时稍后重试，不要填写 GitHub 密钥。
- **登录或授权受阻**：核对官方页面的账号、仓库权限、验证码或双重验证提示。Cloudflare 应选择已核验的同一个 Fork。
- **提示数据库编号缺失或无效**：在原项目构建普通变量中填写 `MU_D1_DATABASE_ID`，值是专用 D1 的 **Database ID**，不是名称；不要重复建库。旧安装使用原库编号。
- **构建访问 D1 无权限**：默认构建令牌没有 D1 权限，在 **My Profile → API Tokens** 给本次构建使用的令牌增加 **Account → D1 → Edit**，保留原权限，再重试原项目。[完整配置步骤](INSTALL.md#第三步安装到-cloudflare)
- **找不到部署程序或部署命令失败**：核对根目录 `backend`、构建命令留空、部署命令 `npm run deploy`，并选择准备页显示的分支。
- **代码已部署但提示安装配置缺失**：在 Worker **Settings → Variables and Secrets** 添加 `INSTALL_CONFIG` **Secret**，粘贴原配置并保存部署。只填 Build Secret 不会配置运行中的后台。
- **复制失败或配置无效**：恢复原 `MU-installation` JSON，重新复制 `MUINSTALL1.` 开头的完整长字符串，不能用配对码替代。
- **创建资源或部署中断**：检查已经创建的 Worker、D1 和 Workflow，保留原配置，在原项目修正并重试。
- **额度或付款提示**：先核对套餐与费用，不要盲目开通付费项目。

反馈时只提供不含秘密的错误提示、版本、设备和失败步骤，不公开安装文件、完整日志或私人聊天。

## 后台地址打开后为什么不是聊天页面？

它是你的后台服务入口，页面提供用途说明和聊天网页链接。请打开聊天网页，在“设置 → 个人后台”连接并检查连接状态，再发送一条测试消息；使用通知时，还需开启相应系统权限。

## 网页能打开，但后台连接不上？

核对后台 URL、对应配对码，以及当前网页是否在该安装配置的准确允许来源中。不同域名不能自动互换。再检查自己的云资源、额度及网络，连接失败不会自动改用作者的后台。

网页和后台的网络可达性需要分别确认；更换 Cloudflare Pages / Netlify 网页不一定能解决 workers.dev 无法连接的问题。

## 关闭准备页、清缓存或换浏览器怎么办？

打开[安装准备页](https://mu-beta.pages.dev/install.html)，点“恢复已有安装备份”，选择原 `MU-installation-….json`，再点“4. 连接后台”复制配对码，不要重新生成配置。[完整恢复步骤](INSTALL.md#找回配对码)

清网站数据或结束隐私浏览可能删除本环境的准备页内容、设备凭据和已保存配对码；切换浏览器不会自动带入这些内容。原来下载的安装文件需要另行保管。新设备需要重新配对；旧聊天记录请另用应用备份迁移。

如果只是忘记配对码，已有设备通常仍可使用；先在原设备编辑连接查看已保存的配对码，或恢复原安装文件。文件也丢失时保留现有云资源并寻求恢复帮助，不要重新生成加密和通知密钥。已登记设备的访问权限需要单独处理，遇到异常请按[安全说明](../SECURITY.md)联系作者。

## 自定义模型中转地址能用吗？

支持符合当前模型接口规则的公网 HTTPS 中转地址，包括自定义域名与端口；不支持内网、IP 直连、凭据嵌入 URL、跳转或任意管理接口。模型、协议、路径和授权方式仍须与服务商匹配。不要为排错关闭鉴权；反馈服务域名和脱敏错误即可。

已绑定中转地址的 API Key 会按已有连接配置测试；绑定多个连接时，先选择本次要测试的连接。个人后台的“检查连接”只检查服务与设备的连接，模型测试仍在原 API Keys／模型设置中进行。

## 我的数据会经过作者后台吗？

个人后台版的模型、语音和后台任务使用你当前连接的实例，连接失败时暂停相应请求。网页下载经过网页托管平台，联网调用 AI 时，相关上下文、媒体和凭据由你的云平台及所选服务商处理。详见[隐私与数据说明](../PRIVACY.md)。

## 为什么后台任务暂停，或者旧结果找不到了？

每个设备、每个后台实例在每个 UTC 日各最多执行 500 次后台任务，当前限额固定。任一限额用完时，相应的新后台模型任务会暂停，已有结果仍可收取，下一 UTC 日恢复。普通前台聊天不计入此后台任务限额；云平台和 AI 服务商的额度及计费规则仍分别适用。

云端结果最多保留 72 小时，收取确认后清除。请及时打开应用收取并备份重要内容；模型和平台还可能另有限制。

## 更新、迁移与停用

### 怎样更新？

先备份，关闭后台回复和自主聊天，确认云端停止并收取在途结果。使用统一网页时，网页由提供方更新；自己的后台由自己更新。开始前阅读本次 [Release](https://github.com/richzorya/mind-universe-release/releases) 的兼容与迁移说明，并保留原安装备份。

**通过本版 Fork 流程安装的后台：**

1. 打开原 Worker 的 **Settings → Build**，确认连接的是自己的 Fork 和原默认分支；保留原 `MU_D1_DATABASE_ID`、Worker 名称和运行时 `INSTALL_CONFIG`。数据库编号仍指向原库，构建令牌仍需 D1 编辑权限。
2. 在 GitHub 打开自己的 Fork，点 **Sync fork → Update branch**。如果出现冲突或提示自己修改过同一文件，先解决冲突并保留安装配置，不要用丢弃修改的方法强行覆盖。[GitHub 同步说明](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/syncing-a-fork)
3. 等原 Worker 的构建记录出现这次提交并成功。未自动开始时，在原项目手动触发构建，核对根目录 `backend`、构建命令留空、部署命令 `npm run deploy`，不要创建新 Worker。
4. 在应用“设置 → 个人后台”点“检查连接”，再发一条测试消息。确认正常后，按需要重新开启后台功能。

**旧自动复制、导入或手动安装的独立副本：**

可以继续使用，不强制转为 Fork；新建 Fork 不会自动接管原后台。更新时从本次 Release 下载 `mind-universe-cloudflare-backend.zip`，先留存原安装文件，再把新版后台文件更新到**原仓库的原后台目录**。其中 `wrangler.jsonc` 要保留原 Worker `name`、真实 D1 `database_id`、数据库名称及两条 Workflow 的 `name`，不能以模板占位值替换；Cloudflare 运行时的原 `INSTALL_CONFIG` 也继续保留。按新版模板设置原项目部署命令 `npm run deploy`，部署并检查连接。原配置已有真实数据库编号时可继续使用；若另填构建变量，其值必须与原库一致，否则部署会停止。

旧配置的 Worker 名必须与原 Cloudflare 项目一致，部署脚本保留原 Workflow 名称，不替换既有资源。不要为更新重新生成安装配置、数据库或任务流程；不熟悉配置合并时先保留正常运行的旧后台，提供脱敏错误寻求帮助。数据库迁移后，直接上传旧版程序不一定能回退。

旧命令行安装仍沿用原私有安装目录与 `--apply`，不重新执行 `--prepare`。不要把两种安装方式的秘密混用。

### 多个后台怎样切换？

可以保存多个后台，选择当前要连接的一个。切换或断开前先停用原后台任务，确认云端清理并收取结果；无法确认时保留原连接。后台列表保存在当前设备，当前页面使用其中选中的一个。其他设备需要分别保存连接。

### 已保存的后台怎样修改？

点“已配对”旁的“编辑”。改名称可以直接保存；本机已保存的配对码默认隐藏，可用小眼睛查看或点“复制配对码”。改地址或配对码需重新连接验证，失败保留原连接；也可点“重新配对”恢复设备授权。编辑未启用的后台不会自动切换当前后台。

旧记录没有配对码时，点“导入安装备份”选择原文件；后台身份一致并重新配对成功后才保存。如果只是读取本机凭据失败，先按错误处理，不把读取失败当成没有配对码。恢复详情见[找回配对码](INSTALL.md#找回配对码)。

### 连接成功在哪里看？

“连接”和“检查连接”旁显示检查进度、绿色对勾“已连接”或本次错误。修改连接信息后需要重新验证。后台检查验证服务与设备连接；模型是否能返回内容仍到原 API Keys／模型设置中测试。

### 换手机、浏览器或网址呢？

先在旧设备、旧网址导出备份，再到新环境导入并配对。同一个 Cloudflare 账号不会自动同步聊天和 API Keys。更换网页域名还需调整后台允许来源，保留原身份和密钥，不能通过重新生成配置来“更新网址”。

### 不用了，怎么停用？

先停止后台回复和自主聊天、确认云端停止、收取结果并导出备份，再断开应用连接。断开不会自动删云资源或撤销设备。

确定不再需要时，在自己 Cloudflare 的该安装项目中逐项核对 Worker、两个 Workflow 和 D1 后手动删除，不要删其他项目。删除数据库后，重新安装不能恢复其中数据。关闭网页或本地断开后，云端任务仍需按前述步骤单独停用；平台既有费用和备份按平台规则处理。

## 群设置和内容管理需要群主或原作者吗？

不需要。你是本机应用的使用者，当前可进入的群都可以管理，包括群资料、成员、背景和自主聊天。可见消息、朋友圈与评论、豆吧帖子与回复也可以管理；编辑不会把原作者改成当前本人。

打开群聊天右上角的群信息，选择“清空聊天记录”并确认，即可清除该群记录并使未完成的旧轮次作废；保留群、角色记忆与自主聊天配置，已开启时从空历史继续。群免打扰由所有本人身份共用，从任一身份修改都会对该群全体生效。“删除群聊”会删除整群及共享消息；只想让当前本人离开时使用“退出群聊”。固定群主身份仍作为群归属保留，不能从成员中移除。

管理不改变当前本人的可见范围。数据正在保存、消息生成尚未结束或记录仍被人物侧写引用时，相关操作会提示具体处理办法；切换身份后请重新确认操作。

## 角色会主动发起私聊吗？

当前尚未实现“用户没有先发消息，角色自行决定时间并主动发起私聊”。已有群角色自主聊天是在群内继续交流；后台回复用于继续处理已提交的回复任务。这些功能不会自动变成角色主动私聊，开启通知也不会让角色开始主动联系。

## 城市为什么变成固定八座？

世界地图与档案馆现在使用同一组八座城市。可以在档案馆修改城市名称，地图会同步显示新名称；不再新增或删除城市。

升级时，历史未对应城市的居民会归入临界城。旧角色姓名去除首尾空白后完全相同的，保留一个活动档案并归入临界城；关联聊天和历史记录会对应到保留档案。合并前的旧资料保存在本机迁移前快照中，重要资料也请另做备份。以后新建或普通导入的不同角色允许同名，不会继续按姓名自动合并。
