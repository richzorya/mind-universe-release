# 安装教程

[返回首页](../README.md) · [遇到问题](FAQ.md)

Mind Universe 仅供个人学习和技术交流使用。安装、使用和分享前，请阅读[学习交流使用条款](../LICENSE.txt)、[免责声明](../DISCLAIMER.md)及[隐私与数据说明](../PRIVACY.md)。任何商业化行为均须事前联系作者并取得另行明确书面授权，包括售卖产品链接或邀请码、收费代部署个人后台、收费托管维护，以及通过本产品以其他方式牟利。

网页是你使用的界面，个人后台负责连接 AI 和处理后台任务。可以直接使用统一网页，只把后台部署到自己的 Cloudflare。下面四步与安装准备页一致，通过浏览器完成，手机和电脑均可操作，无需终端命令。当前为内测版，具体使用条件见[更新记录](../CHANGELOG.md#使用说明)。

## 快速入口

- 日常聊天：[Cloudflare 网页](https://mu-beta.pages.dev/) · [Netlify 网页](https://mu-beta.netlify.app/)。选一个作为日常入口，不必同时使用。
- 安装与恢复资料：[安装准备页](https://mu-beta.pages.dev/install.html) · [Netlify 准备页](https://mu-beta.netlify.app/install.html)。已有安装请选择“恢复已有安装备份”。
- 管理自己安装的后台：[Cloudflare 项目列表](https://dash.cloudflare.com/?to=/:account/workers-and-pages)。登录后选安装时用的账号；若停在账号首页，再打开“Workers & Pages”。
- 已部署却找不到内容：[找回后台地址](#找回后台地址) · [找回配对码](#找回配对码)。不需要重新创建后台。

## 先认清要用的内容

URL 就是网址。下面几项用途不同，不能互相替代；操作步骤会使用与页面一致的按钮名称。

| 内容是什么 | 去哪里复制或取得 | 用在哪里 |
| --- | --- | --- |
| 聊天网页地址：平时打开应用的网址 | 上方“日常聊天”链接 | 打开聊天应用、添加到主屏幕 |
| 安装备份：`MU-installation-….json` 文件 | 准备页“1. 准备资料”→“保存安装备份” | 本人私下保管；需要恢复时选择这个文件，无需手动复制文件内容 |
| 自己的 Fork 仓库地址 | GitHub 完成 Fork 后的仓库首页 | 准备页“2. Fork 仓库”核验；Cloudflare 连接这个仓库 |
| D1 数据库编号：Database ID，形如 UUID 的一串编号 | 自己 Cloudflare 的专用 D1 数据库页面 | 构建普通变量 `MU_D1_DATABASE_ID`，不是数据库名称 |
| 安装配置：以 `MUINSTALL1.` 开头的整段文字 | 准备页“3. 安装到 Cloudflare”→“复制安装配置” | Worker 的 `INSTALL_CONFIG` Secret；字段名不是要填写的值 |
| 后台地址：一般以 `workers.dev` 结尾 | Cloudflare 原 Worker 的 Domains 页（旧界面为 Settings → Domains & Routes） | 应用“设置 → 个人后台 → 连接后台”里的“后台地址” |
| 配对码：允许设备连接后台的口令 | 准备页“4. 连接后台”→“复制配对码”；成功保存后也可在应用编辑连接时查看 | 同一连接表单里的“配对码”，不填到 Cloudflare |
| 模型／语音 API Key | 对应服务商的账号管理页面 | 应用原有“API Keys”页面；已经配好的密钥与模型继续用 |

安装配置和配对码由 Mind Universe 在你的设备上生成，不是 Cloudflare 账号密码。安装备份包含秘密，但**不包含后来部署出来的后台地址，也不是聊天记录备份**。请另外收藏后台地址和 Cloudflare 项目管理页；不要将配对码拼进网址或公开分享安装文件。

## 安装前准备

- 自己的 GitHub 和 Cloudflare 账号；验证码、双重验证与授权提示由你本人完成。
- 自己的模型 API Key；需要语音时再准备相应服务的凭据和权限。
- 手机“文件”或其他本人独占的保存位置，用于保管安装配置。
- 能连接所选网页、GitHub、Cloudflare 及后台的网络。

首次使用 Cloudflare 时，按官方页面完成账号验证、Workers 开通和 workers.dev 子域名设置。创建资源会占用你自己的云平台额度；出现付费升级或付款提示时，先确认费用，不要为了继续而盲目接受。

## 第一步：准备资料

打开[安装准备页](https://mu-beta.pages.dev/install.html)，备用地址是 [Netlify 准备页](https://mu-beta.netlify.app/install.html)。

1. 使用上方两个内测网页时，不用修改地址选项。只有自行部署了聊天网页的人，才展开“我要使用自己部署的网页”，添加自己的 HTTPS 网页根地址；不带路径、参数或通配符。
2. 第一次安装点“生成安装资料”。以前已经安装过的人应点“恢复已有安装备份”，选择原文件，不要重新生成。
3. 点“保存安装备份”，下载 `MU-installation-….json`。在手机“文件”或电脑下载列表中确认文件已保存；具体位置取决于浏览器设置。
4. 保存后点“我已保存，下一步”，进入“2. Fork 仓库”。

**先保存，再离开页面。** 剪贴板会被后续复制覆盖，清网站数据或换浏览器也可能丢失临时资料。安装失败、更新或换设备时继续用原文件。

## 第二步：Fork 仓库

Fork 是 GitHub 为你的账号创建、并保留官方来源关系的仓库。Cloudflare 需要读取这个仓库里的后台程序，才能部署并在你更新仓库后重新发布。

1. 在准备页点“Fork 官方仓库”，或打开[官方 Fork 入口](https://github.com/mind-universe-studio/mind-universe-release/fork)。登录自己的 GitHub 账号。
2. 选择自己的账号作为 Owner，确认仓库名，点 **Create fork**。同一账号已经 Fork 过时，使用自己的现有 Fork。
3. 复制新仓库首页网址，格式是 `https://github.com/你的用户名/你的仓库名`。从手机地址栏复制的 `github.com/…`（不带 `https://`、末尾带 `/`）也可以直接粘贴。不要复制官方仓库 `mind-universe-studio/mind-universe-release`、文件页或 Cloudflare 管理链接；填了官方仓库，页面会提示改填你自己的 Fork。
4. 回到准备页，粘贴到“你的 Fork 仓库地址”，点“核验 Fork 仓库”。页面读取 GitHub 的仓库来源信息；核验成功显示“已核验 Fork”和仓库名，才可进入“3. 安装到 Cloudflare”。

仓库或用户名改名后，粘贴新的网址重新核验；只要仍保留官方 Fork 来源关系，改名不影响来源核验。无法核验时，按页面提示检查链接、公开可见性及 GitHub 请求限制后重试。

通过模板复制、导入或上传文件创建的独立仓库不计入官方 Fork 数量，也不会因填写网址而变成 Fork。新安装请完成上述 Fork 后直接连接该仓库，不再使用旧的自动复制部署入口。已有独立副本的后台可以继续使用，见[更新与旧副本维护](FAQ.md#怎样更新)。

## 第三步：安装到 Cloudflare

Cloudflare 将后台项目叫作 **Worker**。这一步要创建专用数据库、连接你的 Fork，再保存安装秘密；配对码留到第四步填写。

### 1. 创建专用数据库

1. 在准备页展开“创建专用数据库”，点“打开 Cloudflare D1”，或从 Cloudflare 进入 **Storage & databases → D1**。
2. 在安装后台所用的同一账号中创建一个**本次安装专用**的数据库。名称自己取，例如 `mu-personal-db`。
3. 打开新数据库，复制 **Database ID**。这是形如 `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` 的编号，不是数据库名称；稍后填入构建变量。

D1 保存后台的设备配对、任务和回复等数据。没有有效数据库编号，当前部署流程会停止；已有 Worker 缺少数据库绑定时，依赖数据库的配对与后台任务也无法正常工作。不要使用其他应用的数据库。已有后台更新时必须使用原库，不能按此处新建替换。

### 2. 连接 Fork 并部署

1. 展开“连接 Fork 并部署”，点“打开 Cloudflare 项目列表”。创建应用时选择 **Worker**，再选择连接已有 GitHub 仓库的方式。
2. 连接自己的 GitHub 账号，在官方授权页仅授权本次要部署的 Fork。回到 Cloudflare，选准备页已经核验的那个仓库。
3. 按下面表格填写。分支以准备页显示的已核验仓库默认分支为准，通常是 `main`；只启用这条分支的构建，不启用其他分支预览构建。

| Cloudflare 字段 | 填写内容 |
| --- | --- |
| 项目名称 / Project name | **改不改都可以。** 可保持 Cloudflare 默认填入的仓库名，也可改成好认的名字，例如 `mu-personal`；长度为 1–63 个字符，只用小写字母、数字和中划线，不能以中划线开头或结尾。提示名称已存在时换一个名字即可，不要为此删除已有项目。连接时复制 Cloudflare 按这个名称生成的实际网址 |
| 部署命令 / Deploy command | `npm run deploy`（替换默认的 `npx wrangler deploy`） |
| 构建命令 / Build command | 留空 |
| 路径 / Path（建好后在设置里叫“根目录 / Root directory”） | `backend`，在“高级设置”里 |
| API 令牌 / API token | 保持默认或选“创建新令牌”均可，在“高级设置”里 |
| 变量 / Variables（构建变量） | 普通变量 `MU_D1_DATABASE_ID`，值为刚才的 Database ID，在“高级设置”里，**最后填** |
| 分支 / Git branch | 准备页显示的该 Fork 默认分支 |

**Cloudflare 新建页面的操作顺序：** “路径”、“API 令牌”和“变量”默认折叠在页面下方的 **高级设置 / Advanced settings** 里，要先点开。**先选好 API 令牌，最后再填变量**——切换令牌后已填好的变量可能被重置。点 **部署** 前往下滚动核对一次：路径是 `backend`，变量名和数据库编号都还在。漏填或被清空时部署会停止并提示数据库编号缺失，此时到原项目 **Settings → Build** 补上变量后重试这次构建，不要另建项目。

**关于 D1 权限：** 可先使用默认或新建的 Workers Builds 构建令牌，D1 权限以本次令牌的实际配置为准。若 Cloudflare 构建日志明确提示 D1 权限不足，在 **My Profile → API Tokens** 找到该构建使用的令牌，保留原权限并增加 **Account → D1 → Edit**，账号范围包含本次安装账号，保存后在原项目重试构建。只看到“数据库初始化或升级未完成”时，先查看前面的具体错误；数据库 ID、额度等问题也可能导致初始化失败，不必因此更改令牌。[Cloudflare 构建配置与令牌说明](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/#api-token)

无需把令牌内容填入 Mind Universe，也不要提交到 GitHub。若构建失败，先检查原项目的构建设置、数据库编号和错误提示，修正后在原项目重试。部署脚本会连接这份数据库并部署后台及任务流程。

### 3. 保存安装秘密

构建成功后，后台仍需要原安装配置才能连接设备：

1. 回到准备页，展开“保存安装秘密”，点“复制安装配置”。复制以 `MUINSTALL1.` 开头的**整段文字**，不要复制整个 JSON 文件，也不要用配对码替代。
2. 在刚部署的 Worker 打开 **Settings → Variables and Secrets → Add**。
3. 类型选 **Secret**，名称填 `INSTALL_CONFIG`，值粘贴刚才的完整配置。
4. 点 **Deploy** 保存生效。已有同名配置但填写错误时，重新粘贴**同一份**配置，不要生成新配置覆盖旧后台。

**Build variables and secrets 只在构建时可用。** 把 `INSTALL_CONFIG` 放在 Build Secret 中不能完成后台运行配置；它必须放在上面的 Worker **Variables and Secrets** 中。`MU_D1_DATABASE_ID` 则属于前面的普通构建变量。[Cloudflare 变量区别](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/#overview) · [Secret 操作说明](https://developers.cloudflare.com/workers/configuration/secrets/)

Secret 保存后平台会隐藏值，不能从设置页读取配对码。配置缺失或无效时，业务接口会拒绝请求。保留原准备页，点“安装成功，下一步”进入“4. 连接后台”。

<a id="没有出现-install_config-输入框"></a>

没有找到 `INSTALL_CONFIG` 输入框时，按上面“保存安装秘密”在已创建的 Worker 里添加；不需要重新 Fork 或创建第二套后台。

## 第四步：连接后台

### 找回后台地址

部署成功页面关掉了也能找到，不需要重新部署：

1. 打开 [Cloudflare 项目列表](https://dash.cloudflare.com/?to=/:account/workers-and-pages)，登录安装时的账号。
2. 在 **Workers & Pages** 中选安装时的 **Worker 项目**（名称是你安装时填写或保留的项目名称）；不要进入 D1 或 Workflow 列表。
3. 打开 **Domains（域名）** 页，找到 **workers.dev**；旧界面入口为 **Settings → Domains & Routes**。复制它的完整 HTTPS 地址；如果只显示域名，在开头补 `https://`。不要选带版本编号的临时 Preview URL。[官方路径说明](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)

地址格式为 `https://你的Worker名称.你的账号子域.workers.dev`；请复制自己项目的真实值。**不要复制 `https://dash.cloudflare.com/…` 管理页、GitHub 仓库链接、数据库编号或聊天网页地址。** 没有地址或访问入口已停用时，检查原项目的部署记录与提示，不要另建一套。

以前连接成功过，也可在同一个聊天网页的 **设置 → 个人后台** 查看当前地址及“已保存的后台”。安装备份文件不含后来部署的地址。直接打开后台地址会看到后台说明页，日常聊天仍使用本文开头的网页。

### 找回配对码

配对码由安装准备页生成，**Cloudflare 部署完成不会另发配对码**。

- **本机连接已经保存过配对码：** 打开应用“设置 → 个人后台”，点该后台“已配对”旁的“编辑”。配对码默认隐藏，点小眼睛查看，或点“复制配对码”。
- **旧连接提示本浏览器尚未保存配对码：** 在该后台的编辑表单点“导入安装备份”，选择原 `MU-installation-….json`。应用核对文件中的后台身份与该连接是否相同，再向原后台重新配对；成功后才在本机保存配对码。后台离线、文件不匹配或配对失败时，按显示的错误处理，原连接保留。
- **原准备页还开着：** 点顶部“4. 连接后台”→“复制配对码”；展开“查看配对码”可看原文。
- **准备页关了或换设备：** 打开[安装准备页](https://mu-beta.pages.dev/install.html)，点“恢复已有安装备份”，选择原文件，再点“4. 连接后台”复制。不需要重新 Fork 或部署。
- **复制按钮失败：** 显示配对码后长按文字，全选、复制。复制整串口令，不是 `MUINSTALL1.` 开头的安装配置。

配对码不会从服务器自动找回。原备份和本机已保存的配对码都丢失时，先保留现有连接、Worker、数据库及配置，查找下载文件或原设备；不要重新生成安装秘密覆盖旧后台。

### 填写并检查连接

1. 打开[Cloudflare 聊天网页](https://mu-beta.pages.dev/)或[Netlify 聊天网页](https://mu-beta.netlify.app/)，进入 **设置 → 个人后台 → 连接后台**。
2. “连接名称”选填自己容易识别的名字；先把 Worker 的 HTTPS 地址粘贴到“后台地址”。
3. 再复制配对码，粘贴到“配对码”。两次复制之间先粘贴好前一项，避免剪贴板覆盖。
4. 可用小眼睛核对内容，点“连接”。按钮旁出现绿色对勾“已连接”表示配对和必需功能检查通过；“检查连接”可再次验证。
5. **原 API Keys、模型与语音设置继续使用。** 首次使用且尚未配置时才到原页面填写。发一条不含隐私的测试消息，确认能收到回复。

配对成功后，本机独立设备凭据库保存配对码，编辑时默认隐藏。改名称可以直接保存；改地址或配对码需重新验证，失败保留原连接。导入原安装备份也会实际重新配对。普通聊天备份与 API Keys 包不包含后台配对码和设备凭据，换网址、浏览器或设备需要分别连接。

两个内测网页可使用同一个后台地址和配对码，默认安装配置允许它们连接；两边的聊天、密钥与连接记录仍分别保存在各自网址下。日常固定使用一个入口，更换前先备份。

连接完成后，可在群聊天右上角进入群信息，调整自主聊天或清空记录；当前本人无需是群主。[管理与清空说明](FAQ.md#群设置和内容管理需要群主或原作者吗)

## 添加到主屏幕

- iPhone：在 Safari 分享菜单中选择 **添加到主屏幕**。
- Android：使用支持网页应用安装的浏览器，选择 **安装应用 / 添加到主屏幕**。

从主屏幕图标打开后，再确认个人后台和模型设置。不同浏览器、网址以及主屏幕应用不一定共享存储，必要时重新配对；聊天记录需通过备份导入，不会因登录同一个 Cloudflare 自动出现。电脑不需要保持开机。

## 多个后台与更新

可以保存多个后台，当前页面使用其中选中的一个。切换前先关闭原后台回复和自主聊天，确认云端停止、收取在途结果；无法确认时保留原连接，先恢复旧后台。

更新沿用原 Worker、D1、两个 Workflow 和原 `INSTALL_CONFIG`。Fork 后作者发布不会自动更新你的仓库，需要在自己的仓库同步上游，再由原 Worker 部署；旧独立副本也不强制迁移为 Fork。具体步骤见[更新、迁移与停用](FAQ.md#更新迁移与停用)。

## 网页自行托管与旧安装方式

当前网页 ZIP 尚未开放下载，请使用本文顶部的两个内测网页。后续是否提供下载、适用范围和安装方法，以作者正式发布的版本说明及[学习交流使用条款](../LICENSE.txt)为准。

已有旧命令行安装的用户，请继续保留原安装目录和密钥，并按对应版本说明更新。旧 `install.mjs` 面向 macOS / Linux；手机和 Windows 用户请使用本文的浏览器安装流程。

## 使用系统伙伴

以下为 BUILD 222 Preview 的使用说明，公开内测网页本次尚未同步这项功能；请以门厅版本和实际入口为准。

打开手机助手，选择“系统伙伴”，创建模板或自定义档案。先在“模型设置”选择已配置 API Key 的模型，再发送消息；发送按供应商规则计费。每条请求可查看原文、用量和费用状态。失败时先“恢复已有回复”，不会重新调用；“重新请求”可能再次产生费用，需要明确确认。使用帮助仍可离线打开。

“共同记忆”保存你明确确认的内容，可以修订、停用和查看来源。“故事绑定”选择已准备的故事并确认当前人格；后来改档案或切换默认系统不会改写旧绑定。备份时勾选“系统伙伴”保存完整历史，导入不会自动重发在途请求。
