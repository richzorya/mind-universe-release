# 安装教程

[返回首页](../README.md) · [遇到问题](FAQ.md)

Mind Universe 仅供个人学习和技术交流使用。安装、使用和分享前，请阅读[学习交流使用条款](../LICENSE.txt)、[免责声明](../DISCLAIMER.md)及[隐私与数据说明](../PRIVACY.md)。任何商业化行为均须事前联系作者并取得另行明确书面授权，包括售卖产品链接或邀请码、收费代部署个人后台、收费托管维护，以及通过本产品以其他方式牟利。

网页是你使用的界面，个人后台负责连接 AI 和处理后台任务。可以直接使用统一网页，只把后台部署到自己的 Cloudflare。下方主要流程通过浏览器完成，手机和电脑均可操作，无需终端命令。当前为内测版，具体使用条件见[更新记录](../CHANGELOG.md#使用说明)。

## 快速入口

- 日常聊天：[Cloudflare 网页](https://mu-beta.pages.dev/) · [Netlify 网页](https://mu-beta.netlify.app/)。选一个作为日常入口，不必同时使用。
- 安装与恢复资料：[安装准备页](https://mu-beta.pages.dev/install.html) · [Netlify 准备页](https://mu-beta.netlify.app/install.html)。已有安装请选择“恢复已有安装备份”。
- 管理自己安装的后台：[Cloudflare 项目列表](https://dash.cloudflare.com/?to=/:account/workers-and-pages)。登录后选安装时用的账号；若停在账号首页，再打开“Workers & Pages”。
- 已部署却找不到内容：[找回后台地址](#找回后台地址) · [找回配对码](#找回配对码)。不需要重新创建后台。

## 先认清要用的内容

URL 就是网址。下面几项用途不同，不能互相替代；操作步骤会使用与页面一致的按钮名称。

| 内容是什么 | 去哪里复制或取得 | 用在哪里 |
| --- | --- | --- |
| 聊天网页地址：你平时打开应用的网址 | 上方“日常聊天”链接 | 打开聊天应用、添加到主屏幕；不是“后台地址”栏要填的内容 |
| 安装备份：`MU-installation-….json` 文件，保存找回安装资料所需的秘密 | 准备页“1. 准备资料”→“保存安装备份” | 保存在本人私有文件中；丢失页面内容时用“恢复已有安装备份”选择它，不需要手动打开或复制文件内容 |
| 安装配置：以 `MUINSTALL1.` 开头的整段文字，供 Cloudflare 配置你的后台 | 准备页“2. 安装到 Cloudflare”→“复制安装配置”；“查看安装配置”可显示原文 | 粘贴到自己 Worker 的 `INSTALL_CONFIG` Secret（秘密）字段；`INSTALL_CONFIG` 是字段名，不是要填写的值 |
| 后台地址：你刚部署的服务的网址，一般以 `workers.dev` 结尾 | Cloudflare 原项目“Settings → Domains & Routes”中的 `workers.dev` 地址 | 应用“设置 → 个人后台 → 连接后台”里的“后台地址” |
| 配对码：允许设备连接这个后台的口令，不是短信验证码 | 准备页“3. 连接后台”→“复制配对码”；“查看配对码”可显示原文 | 同一连接表单里的“配对码”，不是填到 Cloudflare |
| 模型／语音 API Key：调用你所选 AI 服务的密钥 | 对应服务商的账号管理页面 | 应用原有“API Keys”页面；已经配好的密钥与模型继续用 |

安装配置和配对码由 Mind Universe 在你的设备上生成，不是 Cloudflare 账号密码。安装备份包含秘密，但**不包含后来部署出来的后台地址，也不是聊天记录备份**。请另外收藏后台地址和 Cloudflare 项目管理页；不要将配对码拼进网址或公开分享安装文件。

## 安装前准备

- 自己的 GitHub 和 Cloudflare 账号；验证码、双重验证与授权提示由你本人完成。
- 自己的模型 API Key；需要语音时再准备相应服务的凭据和权限。
- 手机“文件”或其他本人独占的保存位置，用于保管安装配置。
- 能连接所选网页、GitHub、Cloudflare 及后台的网络。

首次使用 Cloudflare 时，按官方页面完成账号验证、Workers 开通和 workers.dev 子域名设置。创建资源会占用你自己的云平台额度；出现付费升级或付款提示时，先确认费用，不要为了继续而盲目接受。

## 第一步：生成并保存安装资料

打开[安装准备页](https://mu-beta.pages.dev/install.html)，备用地址是 [Netlify 准备页](https://mu-beta.netlify.app/install.html)。

1. 使用上方两个内测网页时，不用修改地址选项。只有自行部署了聊天网页的人，才展开“我要使用自己部署的网页”，添加自己的 HTTPS 网页地址；只填写协议和域名，不带路径、参数或通配符。
2. 第一次安装点“生成安装资料”。这会生成安装配置和其中的配对码；以前已经安装过的人应[恢复原备份](#找回配对码)，不要重新生成。
3. 点“保存安装备份”，下载 `MU-installation-….json`。在手机“文件”中确认文件已保存；可以查看“最近项目”，或到 iCloud 云盘／我的 iPhone 中实际设置的下载位置找，保存位置取决于浏览器设置。电脑可查看浏览器下载列表。
4. 确认文件已保存后，回到准备页点“我已保存，下一步”。此时进入“2. 安装到 Cloudflare”，能看到“复制安装配置”按钮。

**先保存，再离开页面。** 不要只依赖剪贴板或临时页面：后面复制后台地址会覆盖剪贴板；刷新、清网站数据或切换浏览器可能使临时内容丢失。已有安装要恢复原文件，不要重新生成。

## 第二步：安装到 Cloudflare

这一步使用的是**安装配置**，还不需要填写配对码。Cloudflare 将单个后台项目叫作 **Worker**，后面在项目列表里找的就是它。

1. 在准备页点“复制安装配置”。应复制到以 `MUINSTALL1.` 开头的一整段文字，不能只复制字段名 `INSTALL_CONFIG`，也不要复制整个 JSON 文件。
2. 点“打开 Cloudflare 安装”，或使用[官方部署入口](https://deploy.workers.cloudflare.com/?url=https%3A%2F%2Fgithub.com%2Frichzorya%2Fmind-universe-release%2Ftree%2Fmain%2Fbackend)。保留原准备页，稍后还要回去取配对码。
3. 在 Cloudflare 官方页面登录自己的账号，连接 GitHub，仅授权本次安装所需的仓库。
4. 确认账号与新建项目名称，记下名称，方便以后找回。按钮会把安装模板复制到你的 GitHub 账号，供你按使用条款安装本人的学习交流环境；已装过时沿用原项目。
5. 在名为 `INSTALL_CONFIG` 的 Secret 输入框，粘贴第 1 项复制的整段文字。Secret 是平台保存私密配置的字段类型，不是另一个需要申请的密码。不要填成普通公开变量，也不要提交到 GitHub 文件。
6. 按页面提示确认所需资源并部署，保留模板默认部署命令。数据库（D1）用来保存后台数据，任务流程（Workflow）用来执行后台任务；模板负责部署和连接这些部分，不要删去其中一项。

账号已有有效登录或授权时，不必重新登录。验证码、双重验证、仓库授权和付款确认仍由你本人处理。界面差异可对照[Cloudflare 官方部署按钮说明](https://developers.cloudflare.com/workers/platform/deploy-buttons/)。

### 没有出现 INSTALL_CONFIG 输入框？

不要把配置粘贴进代码或构建日志。在后台项目已经创建后：

1. 打开 [Cloudflare 项目列表](https://dash.cloudflare.com/?to=/:account/workers-and-pages)，选刚才的 Worker。
2. 进入 **Settings（设置）→ Variables and Secrets（变量和秘密）→ Add（添加）**。
3. 类型选 **Secret**；名称填 `INSTALL_CONFIG`；值粘贴准备页“复制安装配置”得到的原始整段文字。
4. 点 **Deploy（部署）** 保存生效。已有同名配置但填写错误时，编辑原字段并重新粘贴**同一份**配置，不要生成新配置覆盖。

Secret 保存后平台会隐藏值，无法把 Cloudflare 设置页当作配对码查询页。[Cloudflare 官方操作说明](https://developers.cloudflare.com/workers/configuration/secrets/)

配置未完成或无效时，业务接口会拒绝请求。不要为排错关闭鉴权或重新生成安装配置。若 Cloudflare GitHub App 授权或创建资源失败，先按页面错误处理，不要连续新建多套后台。

## 第三步：找到后台地址和配对码

### 找回后台地址

部署成功页面关掉了也能找到，不需要重新部署：

1. 打开 [Cloudflare 项目列表](https://dash.cloudflare.com/?to=/:account/workers-and-pages)，登录安装时使用的账号。如有多个 Cloudflare 账号，选择当时创建后台的那个。
2. 在 **Workers & Pages** 中选安装时取名的 **Worker 项目**；不要进入 D1 数据库或 Workflow 任务列表。忘记名称时，先对照刚才的浏览器历史和项目部署记录，不要随便选另一套后台。
3. 在该项目里打开 **Settings（设置）→ Domains & Routes（域名和路由）**，找到 **workers.dev** 那一项。这是后台访问地址；界面位置以当前平台为准，可对照[官方路径说明](https://developers.cloudflare.com/workers/configuration/routing/workers-dev/)。
4. 复制这一项的完整 HTTPS 网址。只有域名时，在开头补上 `https://`；若能点开访问地址，也可以打开后复制浏览器地址栏里的网址。不要选择带版本编号的临时 Preview URL。

要填的格式是 `https://你的Worker名称.你的账号子域.workers.dev`，以上中文只是格式说明，请复制自己项目的真实地址，不要照抄。

**不要复制 `https://dash.cloudflare.com/…` 管理页面地址、GitHub 仓库链接、数据库编号或聊天网页地址。** 若项目没有访问地址，或显示未部署／访问入口已停用，先检查该项目的部署记录和提示，不要新建第二套来找地址。

如果以前已在应用里连接成功，也可打开同一个聊天网页的 **设置 → 个人后台**：当前连接下方会显示地址；其他连接在“已保存的后台”里。安装备份文件本身不包含后台地址。

直接打开后台地址时，会看到个人后台说明页。日常聊天请使用本文开头的网页入口，再在应用设置中连接自己的后台。配对码请从原安装准备页或安装备份中取得。

### 找回配对码

配对码是允许你的设备连接后台的口令。它由安装准备页生成，**Cloudflare 部署完成不会另发一个配对码**。

- **原准备页还开着、资料还在：** 回到该页，点顶部“3. 连接后台”，再点“复制配对码”。想先看内容就展开“查看配对码”。也可从第 2 步点“安装成功，下一步”进入。
- **页面关了、刷新了，或资料不见了：** 打开[安装准备页](https://mu-beta.pages.dev/install.html)或 [Netlify 准备页](https://mu-beta.netlify.app/install.html)，点“恢复已有安装备份”，选择安装时保存的 `MU-installation-….json` 文件；恢复后点“3. 连接后台”→“复制配对码”。不需要再点 Cloudflare 安装按钮。
- **复制按钮没成功：** 展开“查看配对码”，长按文字并选择全选、复制。复制的是里面的整串口令，不是“配对码”三个字，也不是 `MUINSTALL1.` 开头的安装配置。
- **找不到备份：** 先查原准备页、浏览器下载列表和手机“文件”。仍找不到时保留原 Cloudflare 项目，联系帮助时只提供项目名称和不含秘密的错误信息；不要重新生成安装配置覆盖旧后台，以免影响已有数据与通知。

若直接从 GitHub 点部署、从未生成和填写安装配置，还需要为这个后台补齐配置才能连接。确认这是首次创建、没有旧数据的新后台后，按第一步生成并保存资料，再在**这个已有项目**里[补填安装配置](#没有出现-install_config-输入框)；已有后台应恢复原备份，不走重新生成流程。

## 第四步：在应用里填写并检查连接

1. 打开[Cloudflare 聊天网页](https://mu-beta.pages.dev/)或[Netlify 聊天网页](https://mu-beta.netlify.app/)，进入 **设置 → 个人后台 → 连接后台**。
2. **连接名称（选填）：** 自己取一个方便识别的名字，例如“日常使用”，不用从别处复制。
3. **后台地址：** 粘贴从 Cloudflare 项目复制的 HTTPS 访问网址。
4. 回到准备页复制配对码，再切回这个表单，将它粘贴到 **配对码**。手机剪贴板通常只保留最后一次复制的内容，请先粘贴好后台地址再复制配对码。
5. 用地址和配对码旁的小眼睛核对本次输入，点 **连接**。连接操作旁显示绿色对勾和“已连接”表示检查通过；可点 **检查连接** 再次验证，失败原因就近显示。修改地址或配对信息后需要重新验证，不沿用旧成功标识。
6. **原来的 API 密钥与模型继续使用，不需要因为配对重新填写。** 仅首次使用且尚未配置的人，才到原“API Keys”页面保存服务商密钥，并在模型设置中选择模型。最后发一条不含隐私的测试消息，确认能正常收到回复。

已保存的后台在“已配对”旁提供 **编辑**。名称可以直接修改；修改后台地址或重新配对时，填写该后台的配对码，通过验证后才更新连接，失败保留原连接。应用不保存配对码明文，编辑时无法从旧记录显示它；请从原安装备份恢复并重新复制。模型与语音密钥仍在原 **API Keys** 页面管理。

Cloudflare 管理令牌、账号密码不填进应用。模型 API Key、配对码和 `INSTALL_CONFIG` 是三种不同的值。

## 第五步：添加到主屏幕

- iPhone：在 Safari 分享菜单中选择 **添加到主屏幕**。
- Android：使用支持网页应用安装的浏览器，选择 **安装应用 / 添加到主屏幕**。

从主屏幕图标打开后，再确认个人后台和模型设置。不同浏览器、网址以及主屏幕应用不一定共享存储，必要时重新配对；聊天记录需通过备份导入，不会因登录同一个 Cloudflare 自动出现。电脑不需要保持开机。

## 多个后台与更新

可以保存多个后台，当前页面使用其中选中的一个。切换前先关闭原后台回复和自主聊天，确认云端停止、收取在途结果；无法确认时保留原连接，先恢复旧后台。

更新自己的后台时，沿用原 Worker、D1、两个 Workflow 和原 `INSTALL_CONFIG`。作者更新发行仓库后，你自己账号中的副本不会自动获得更新；按对应版本说明更新副本并重新部署。不要再次按首次安装生成新配置或创建替代数据库。

完整说明见[更新、迁移与停用](FAQ.md#更新迁移与停用)。
